# 筛选与归类：哪些该加，哪些是凑数

## 两个信号的读法

`rank.py` 给每个候选两个数：

- **back = 我的多少个种子引用了它。** 这是"领域前置工作"的代理指标。
  `back >= 3` 意味着至少三条独立脉络都绕不开它，漏掉会被审稿人直接点名。
- **fwd = 它引用了我的多少个种子。** 这是"这个方向的重要下游"的代理指标。
  一篇同时引用 ACT、DP、π0 的工作，大概率是本文该出现在同一条谱系里的邻居。

被引量（`cc`）只做同分排序。**不要按被引量从上往下挑**：一个两万引的 ResNet 对本文毫无用处，而一篇 300 引但恰好定义了"空边语义"的图网络论文可能必须引。

## 逐条过筛的问题

1. 我能不能用它支撑正文里已有的一句话？答不出 → 跳过。
2. 它和已有条目重复吗？（同一工作的预印本/会议版/期刊版只留一个）
3. 它是"基础设施"还是"论证"？Adam、ResNet、PyTorch 属于基础设施，除非正文真的讨论优化器/骨干网络，否则不引。
4. 加上它会不会让某一段变成清单？一段超过 8 个并列引用时，考虑拆句或只留最相关的。

## 按段落归类，保证每段都有增量

补文献最容易犯的错是全部塞进 related work 的第一段。按论证功能分：

| 功能 | 典型内容 | 落点 |
|---|---|---|
| 方法谱系 | 本文方法的直系祖先、被对比的架构 | Related Work 第 1–2 段 |
| 机制定义 | 公式里用到的算子/约定的出处（attention、message passing、FiLM） | Method 对应公式处 |
| 评测与协议 | 基准、鲁棒性协议、统计方法 | Related Work 末段 + Experiments |
| 问题背景 | 领域现状、任务重要性 | Introduction |
| 对照与边界 | 相反结论、失败案例、负结果 | Discussion |

一条文献挂在 Method 的公式旁，比挂在 Related Work 的清单里有价值得多。

## 一次真实调研的分布（2026-11，CVPR 投稿）

- 26 个种子（ACT / DP / π0 / OpenVLA / RT-1 / LIBERO / LIBERO-Plus / GAT / Graphormer / R-GCN / CompGCN / Slot Attention / FixMatch / Mean Teacher / IRM / Group DRO / Causal Confusion / Domain Randomization / LoRA / TENT / Set Transformer …）
- 后向 1667 条记录，前向 4545（S2，仅作参考）+ 669（OpenAlex 按被引排序，有效）
- 去重后 5064 个候选标题，其中 **60 篇被 ≥3 个种子引用**
- 最终新增 26 条，50 → 76（正文引用 74）

有价值的观察：

- 该领域的枢纽是 **VLA 谱系**（RT-2、Octo、SmolVLA、Open X-Embodiment、π0.5、GR00T N1、PaLM-E），纯 CV 的鲁棒性文献反而是外围。若只按"鲁棒性"关键词检索，会漏掉一半真正该引的工作。
- 后向树暴露的经典枢纽往往是**跨领域的**：Attention、GCN、MPNN、DomainBed、Temporal Ensembling、DINOv2、Flow Matching。这些不在本文的关键词里，但缺了会显得没读过原文献。
- 有一条最该引的文献（本文第三条 backbone 的开源实现）**从未在正文出现过**——这类"自己用了却没引"的缺口，只有把种子取自现有 bib 再回看才会发现。

## 反模式

- **按被引量倒序批量加**：会加进一堆领域外的高引论文。
- **只做后向**：只能看到老工作，看不到这个方向最近两年谁在引用你的基线。
- **只做前向**：会得到一堆同质的新预印本，缺经典根基。
- **一次加 40 条**：正文挂不住，审稿人一眼看出是凑数。宁可分两次。
- **把新文献单独开一段**：多出来的段落会顶破页数上限，而引用本身几乎不占版面。
